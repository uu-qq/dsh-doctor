# dsh-doctor — 回答失败时，它告诉你到底是谁的错

给 [DeepSeek Harness (dsh)](https://github.com/deepseek-ai/deepseek-harness) 用的小插件。

用 AI 的时候最烦的就是回答突然失败，还不知道为什么：是我的密钥错了？网断了？
还是对方太挤？瞎猜最浪费时间。这个插件就是来分清这件事的 —— 失败一出现，
它直接告诉你**问题出在哪一类、为什么、接下来该怎么办**。

## 它能帮你看出什么（五类问题）

| 它给出的结论 | 大白话 | 你该做什么 |
| --- | --- | --- |
| **API 调用问题** | 你这边递过去的东西不对：密钥错了、模型名写错了、地址拼错了、或者你的账户没钱/没额度了 | 改对了再试，重试一万次也没用 |
| **网络环境问题** | 你家网/代理这一段不通：域名解析不了、连不上、连接中途被掐断 | 先修网络或换个代理节点 |
| **工作环境问题** | 你电脑上的设置写错了，最常见是接口地址多拼了一层 `/v1` | 照它的提示改设置 |
| **上游阻塞** | 对方太挤了：同时用的人太多把你挡回来，或者对方排队排到几十秒才回第一个字 | 等一会儿，或换个不挤的模型 |
| **中转站层问题** | 你用的中转站本身坏了：它背后没通道了、它自己的钱花完了、或者它的网站防护把你挡了 | 等它修好，或者换个站；改你自己的设置没用 |

（前四类是直连官方时会遇到的；第五类是 v0.2 给用中转站的人加的，见下面「中转站用户看这里」。）

## 新手三步上手

**第一步：装上。** 在终端里运行：

```sh
dsh plugin --profile web add github:uu-qq/dsh-doctor
```

**第二步：填两个空。** 打开你 profile 里的 `cordis.patch.yml`，找到 id 是 `doctor` 的那段，
把这两行换成你自己的（其他行不用动）：

```yaml
        baseUrl: 'https://你的服务商给的接口地址/v1'   # 服务商页面上一般叫“API 地址 / Base URL”
        model: '你要用的模型名'                        # 可不填；填了它会多做一次真实的小测试
```

再把你的密钥放进环境变量（密钥不要写进任何文件里，放环境变量最安全）。
Windows（PowerShell）执行一次：

```powershell
setx DSH_DOCTOR_API_KEY "你的密钥"
```

macOS / Linux：

```sh
export DSH_DOCTOR_API_KEY="你的密钥"
```

**第三步：正常用就行。** 以后回答失败时，dsh 会先问它一句再决定怎么办；
你也可以直接问 dsh「刚才为什么失败」。它给出的结论长这样：

```
结论：上游阻塞
依据：对方同时在用的人太多，把你的请求挡回来了（429）。不是你的设置错，也不是网断了。
建议：等一会儿再试，或换一个不那么挤的模型；高峰时段免费额度尤其容易满。
```

## 它是怎么做到的（简单版）

两种办法配合：一是**看报错的话**——每家出错时说的话不一样，它都整理成了规则，
看一眼就知道是哪类；二是**亲自去查一遍**（叫“探测”）：从最底层开始一层层试——
你填的地址对不对 → 网通不通 → 密钥认不认 → 真发一句话过去看它答不答。
坏在哪一层就停在哪一层，不会只丢给你一句“失败了”。

## 中转站用户看这里

很多人不直接用官方，而是先经过一个**中转站**转发（先把请求发给中转站，它再转给官方）。
这一层有它自己独有的坏法，这个插件专门认这些（v0.2 起，默认开启，什么都不用设置）：

- **它背后没通道了**（“无可用渠道”）：站里转发这个模型的路全断了，或你的分组没配这个模型
- **它的防护把你挡了**（Cloudflare 52x、返回一个网页而不是正常回复）：站在维护或被防护误伤
- **你在站里的钱花完了**：注意这是站内账户，和官方账户是两本账
- **站长自己的钱花完了**：你充再多也没用，只能等他补或换站
- **你的分组没权限用这个模型**：去站里看你的令牌属于哪个分组、能用哪些模型

它还能认出对面是不是中转站（看对方的“身份证”——面板特有的标记），
以及识破一种假成功：**嘴上说成功（状态 200）、其实返回的是错误**，探测时不会被它骗成“一切正常”。

## 进阶（看不懂可以跳过）

不装插件、只想在终端里查一次，也可以用独立命令：

```sh
# 只判断一段报错是哪类问题
node lib/cli.js --error "429 model_concurrency_rate_limit_exceeded: At capacity"

# 对一个接口地址做完整探测（密钥放环境变量）
DSH_DOCTOR_API_KEY=你的密钥 node lib/cli.js \
  --base-url https://developer.amd.com.cn/radeon/api/v1 \
  --model MiMo-V2.6-Flash
```

退出码：0 = 全过；2 = 发现问题（已分类）；1 = 命令写错了。
中转规则默认开，`--no-relay` 可以关。插件的完整配置项（都可不填）：

```yaml
        baseUrl: ''                  # 接口地址
        model: ''                    # 模型名，填了才做真实生成探测
        apiKeyEnv: DSH_DOCTOR_API_KEY  # 密钥放在哪个环境变量里
        timeoutMs: 20000             # 每步探测最多等多久
        relay: 'auto'                # 中转规则开关：auto 开 / off 关
```

开发：`npm test` 跑全部测试（node --test，无外部依赖）。目录：
`lib/classify.js` 分类规则、`lib/relay.js` 中转站识别与规则、`lib/probe.js` 分层探测、
`lib/index.js` 插件入口、`lib/cli.js` 独立命令。

## 说明

- dsh 还在开发者预览期，插件接口可能变化；本插件按 2026-11 的插件规范编写。
- 探测的最后一步会真的发一次最小请求（只生成 1 个 token），费用可以忽略，但会占用一次并发。
- 密钥只从环境变量读取，**绝不出现在任何输出里**。
